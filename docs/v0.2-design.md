# v0.2 algorithm design

## Typed contracts and execution

Schema/Shape represent object, array, string, integral, real, boolean and null nodes, their bounds, scalar choices and source paths. Objects retain ordered children plus a precompiled lookup table. Spec retains raw input/output JSON for presentation and v0.1 fingerprint compatibility. Runtime validation and Runner use the compiled IR; validate(JSON, instance) remains a convenience facade.

Adapter carries family, version and an invoke callback returning Result[Json,String]. run_adapter has no embedded demo behavior. The registered fixtures live separately; no dynamic loading, external processes or network adapters are exposed. Outcome records whether invocation happened and how many validation calls actually ran. Error text is not used to infer execution cost.

## Generation and witness coverage

Jobs declare an expected acceptance or specific rejection rule/path before MoonProbe validates them. A mismatch produces ENGINE_EXPECTATION_MISMATCH instead of silently adopting the validator's answer. This detects disagreement, while the independently implemented reference and original upstream expectations guard against common errors.

Each target identifies source path, instance path, rule and witness kind. IDs hash a canonical tuple, including array positions; identical obligations are merged. Expected violations never derive from the validator's return value. Positive constrained endpoints that an enum excludes are explicitly not applicable. A finite enum complement is not applicable only when exhaustion is proved; unsuccessful bounded searches remain uncovered.

Target order round-robins unary jobs by data path before optional-presence pairwise jobs. Pairwise means the four presence/absence combinations for each pair of optional siblings in one object, limited to eight siblings. It is not pairwise coverage over all possible field values or across all nesting levels. Array goals materialize first/middle/last positions where possible; seeded samples use path-separated streams for every item.

A covered target has an actual matching witness in the returned case list. This is conservative witness coverage, not branch coverage or a general coverage guarantee. Excluded and uncovered obligations remain visible. The catalogue counts covered + uncovered + not_applicable consistently. Full witness coverage does not establish semantic correctness.

All produced inputs are deduplicated by canonical JSON. Fixed boundary witnesses are seed-independent; supplemental samples mix seed, case index and path. Proven small finite legal domains stop once enumerated. Otherwise a duplicate-heavy strategy may reach its budget and honestly report budget_exhausted; it must not claim the entire input domain is exhausted. --cases is an upper bound.

## Shrinking

The new reducer lazily emits complement chunk deletions, increasing partition granularity until fine-grained deletion. It recursively visits optional object fields, array intervals and Unicode code-point intervals, then scalar targets such as zero, numeric halves and contract bounds. This is a bounded ddmin-style reduction, not a claim of the complete theoretical ddmin guarantees or a global minimum.

For a legal execution failure, the IR prevents obviously invalid required-field and minimum-length deletions. Every accepted candidate still passes the original input expectation and exactly preserves stage/code/JSON Pointer for the same tool. Negative cases retain their original rejection expectation. Smaller failures of another signature are rejected.

The ranking is lexicographic: structural nodes, canonical UTF-8 bytes, then scalar magnitudes in lexical JSON Pointer order. Numbers use absolute value; false precedes true. Strings only undergo deletion. Thus 4 can reduce to 0 even though both serialize to one byte. Strict descent plus a budget prevents cycles.

Candidate visits include duplicates, invalid inputs and non-improvements. The default budget is 100, CLI maximum 1000. A per-call bounded cache stores validation and Runner outcomes; cached candidates do not call the adapter again. Trace records accepted operations, hashes, sizes and the preserved signature, while rejected categories are summarized. Manual oversized inputs retain the original and return input_budget.

## Reports and compatibility

Format v2 records requested/generated case counts, generator version, witness catalogue, termination, signature groups, individual failure corpora and accepted shrink steps. Main calls, shrink calls, total calls, validation calls and cache hits are separate. adapter_calls remains a main-phase alias for compatibility.

A group identifies one observable signature, not a proven root cause. Different original inputs remain separate corpus entries even if their reductions converge. v1 and v2 corpora can replay under an unchanged v0.1-compatible contract fingerprint. Reproduction uses stored input, not regenerated random sequences.

The archived v0.1 algorithms remain explicitly named reference functions for comparison. Legacy and new attempt counts have different semantics; common adapter-call counts and measured timings are the comparable cost metrics. The original v0.1 delivery is preserved unchanged.
